# Bark 通知测试流程

## 当前目标

已接入价差监控达标告警，支持页面测试、开关、发送结果与记录。独立脚本仍可用于验证下面的通知链路：

```text
本地测试脚本 → Bark 官方服务 → Apple APNs → iPhone 上的 Bark App
```

默认使用 Bark 官方服务 `https://api.day.app`，不需要自行部署服务端。

## 获取设备 Key

1. 在 iPhone 上安装并打开 Bark。
2. 允许 Bark 发送通知。
3. 在 App 中复制测试 URL，格式类似 `https://api.day.app/设备Key/测试内容`。
4. 从 URL 中取出 `api.day.app/` 后面的第一段内容，这就是设备 Key。

设备 Key 相当于推送凭证。不要把它写进代码、提交到 Git，或发送到公开场所。

## 本地验证

先预览请求，不访问网络：

```bash
npm run test:bark -- --dry-run
```

在 zsh 中临时读取设备 Key，输入内容不会显示在终端上：

```bash
read -s "BARK_DEVICE_KEY?请输入 Bark 设备 Key："
export BARK_DEVICE_KEY
```

发送默认测试消息：

```bash
npm run test:bark
```

也可以指定标题和正文：

```bash
npm run test:bark -- --title "价格监控测试" --body "测试消息已触发"
```

命令成功后，以 iPhone 是否实际收到通知作为最终验证结果。测试完成后清除当前终端中的设备 Key：

```bash
unset BARK_DEVICE_KEY
```

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 提示缺少设备 Key | 当前终端是否已经设置 `BARK_DEVICE_KEY` |
| API 成功但手机未收到 | Bark 的通知权限、专注模式和网络状态 |
| 返回设备 Key 错误 | 是否复制了测试 URL 中完整且正确的 Key |
| 请求超时 | 当前机器是否能访问 `https://api.day.app` |

如果以后改用自建 Bark 服务，可以额外设置 `BARK_SERVER_URL`；当前测试不需要该配置。

## 价差监控接入

本地 `./run` 和 `./run dev` 自动读取项目根目录的 `.env`，已有进程环境变量优先，文件不存在时正常启动。修改配置后执行 `./run stop` 再启动；`npm run dev` 的后端启动入口同样自动加载根目录 `.env`；修改后需重启后端。线上安装新版 systemd unit 后会自动读取服务器项目目录的 `.env`，修改后重启服务即可，见 [服务器部署说明](./server-deployment.md#bark-推送环境变量)。不要把设备 Key 放入 localStorage 或前端。

1. 打开价差监控的 Bark 推送区域；未配置时测试和开启按钮不可用。
2. 点击“发送测试通知”，检查手机。页面“Bark 已接收”仅代表服务端接受，不代表手机已经送达。测试不改变监控设置、累计时间或去重轮次；结果写入推送记录。
3. 点击推送开关开启正式提醒。仅参考偏离达到阈值、累计有效时间达标、历史与盘口有效时提醒；每方向每轮一次，恢复后可再次触发，重启保留去重状态。
4. 通知包含方向、参考偏离及阈值、市价偏离、原始市价价差、历史均值/覆盖率、单边金额、容量和累计时间。深度不足不拦截参考信号，正文会明确标记。

测试入口每分钟最多两次；请求超时记为结果未知，不自动重发。可在记录中查看待发送、成功、失败、未知；成功表示 Bark 服务接受。停用推送不会停用看盘，也不会自动重置已通知轮次。
